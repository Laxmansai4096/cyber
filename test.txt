TEST CASE 1.1: OWASP crAPI (Cloud-Native Vehicle Microservices API)
--------------------------------------------------------------------------------
- Target Repository: OWASP/crAPI (https://github.com/OWASP/crAPI)
- Direct Raw Spec URL:
  https://raw.githubusercontent.com/OWASP/crAPI/main/docs/openapi.json
- What to Test:
  1. Open http://localhost:8000 and select the "Phase 1: Architecture Review" tab.
  2. Copy the JSON from the raw URL above (or click "Load Sample API Spec").
  3. Paste into the left input panel and click "Analyze Architecture & Run STRIDE".
- Expected Security Findings & AI Output:
  * Public Internet ➔ Internal API boundary crossings without authentication.
  * PII parameters passed in URL query strings (e.g. /identity/api/auth/v2/user).
  * STRIDE Spoofing (S), Elevation of Privilege (E), and Information Disclosure (I) risks.
  * Gemini AI Advisory Card rendering:
    - ⚠️ What to Update: Flagged unauthenticated routes & cleartext PII query params.
    - 🔧 How to Update: Exact OpenAPI 3.0 security scheme attachments and TLS body relocations.
    - 💡 Strategic Suggestions & 🎯 Prioritized Next Steps.
    - 📚 Regulatory References: NIST SP 800-207 Zero Trust, OWASP API Security Top 10.

  2. Copy the raw Python source code from the link above.
  3. Paste into the left input editor and click "Execute White-Hat Code Review".

TEST CASE 4.1: Live Deployed OWASP crAPI Local Container
--------------------------------------------------------------------------------
- How to Launch crAPI Locally:
  git clone https://github.com/OWASP/crAPI.git
  cd crAPI/deploy/docker
  docker compose -f docker-compose.yml up -d
  (Runs at: http://localhost:8888)
- What to Test:
  1. Go to "Phase 4: Staging DAST & RBAC" tab on http://localhost:8000.
  2. In Base URL, enter: http://localhost:8888
  3. In the Endpoints JSON box, paste:
[
  {
    "path": "/workshop/api/shop/orders/all",
    "method": "GET",
    "is_private_user_resource": true,
    "user_b_response_code": 200,
    "guest_response_code": 401
  },
  {
    "path": "/identity/api/v2/vehicle/101/location",
    "method": "GET",
    "is_private_user_resource": true,
    "user_b_response_code": 200,
    "guest_response_code": 401
  }
]
  4. Click "Execute Stateful DAST & RBAC Probes".
- Expected Security Findings & AI Output:
  * Dual-User RBAC matrix flags Critical BOLA/IDOR when User B receives HTTP 200 OK.
  * Missing security headers (HSTS, Content-Security-Policy, X-Frame-Options).
  * Cloud metadata SSRF probe for http://169.254.169.254.
  * Reproducible non-destructive curl commands for immediate developer validation.
  * Gemini AI Advisory Card rendering:
    - ⚠️ What to Update: Missing tenant ownership filters and wildcard CORS headers.
    - 🔧 How to Update: Centralized tenancy middleware checks and Nginx HSTS/CORS configs.
    - 💡 Strategic Suggestions & 🎯 Prioritized Next Steps (OWASP BOLA references).

TEST CASE 5.1: Multi-Vector Breach Stream (Default Preset)
--------------------------------------------------------------------------------
- Local File: app/samples/runtime_telemetry.json
- What to Test:
  1. Go to "Phase 5: Blue Team SOC & Logs" tab on http://localhost:8000.
  2. Click "Load Breach Telemetry" and hit "Correlate Logs & Detect Threats".
- Expected Security Findings & AI Output:
  * Credential Stuffing (T1110): 5 failed logins followed by success from Moscow.
  * Session Token Hijacking (T1539): Session cookie replayed from Linux/curl in Frankfurt.
  * Impossible Travel: Account active in New York, then Frankfurt in 15 minutes.
  * Mass Data Exfiltration (T1048): Bulk export of 12,500 customer records.
  * Active Honeytoken Canary Triggered: Unauthorized access to decoy AWS key in Amsterdam.
  * Gemini AI Advisory Card rendering:
    - ⚠️ What to Update: Active compromised session tokens and edge firewall ACL rules.
    - 🔧 How to Update: Redis session token purge commands and iptables/WAF block rules.
    - 💡 Strategic Suggestions & 🎯 Prioritized Next Steps (NIST SP 800-61 & MITRE ATT&CK).
- Containment Actions to Test:
  * Click "Level 1: Step-Up MFA" -> Dispatches challenge to target user.
  * Click "Level 2: Revoke Session" -> Invalidates active JWT cookies in Redis.
  * Click "Level 3: Quarantine & WAF Block" -> Generates live AWS WAF / iptables rule
    and logs the action to the real-time Containment Ledger.
